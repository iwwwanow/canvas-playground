# Mosaic Toast — как это работает

## Что происходит

Берём видео → разбиваем каждый кадр на цветовые регионы (прямоугольники) → каждый прямоугольник заменяем фотографией похожего цвета (или заливаем чистым цветом). Результат — мозаика, которая читается как исходное видео, но собрана из текстур.

---

## Пайплайн: 3 независимых шага

```
[1] mosaic frames     — сегментация: видео → segments.json
[2] mosaic render     — рендер:      segments.json + ассеты → mp4
```

Шаг 1 пересчитывается при изменении `--tones`, `--hues`, `--min-region`.
Шаг 2 можно запускать повторно на тех же segments.json с другими ассетами или режимом.

---

## Шаг 1 — Сегментация (`mosaic frames`)

### Постеризация пикселей

Каждый пиксель переводится из RGB → HSV (Hue, Saturation, Value).

Hue и Value квантуются на дискретные уровни:

```
colorClass = hueLevel * tones + valueLevel

где:
  hueLevel  = floor(H / (360 / hues))    — какой оттенок (0..hues-1)
  valueLevel = floor(V * tones)           — какая яркость (0..tones-1)
```

Результат: каждый пиксель получает целый номер `colorClass` от 0 до `hues*tones - 1`.
Малонасыщенные пиксели (серые) попадают в отдельный класс яркости без учёта оттенка.

**Параметры:**
- `--tones N` (4–14) — квантование яркости. Меньше → крупнее блоки по тону
- `--hues N` (4–14) — квантование оттенка. Меньше → крупнее блоки по цвету

### BFS-сегментация

После постеризации каждый связный регион одного `colorClass` обходится BFS (поиск в ширину).
Регионы меньше `--min-region` пикселей выбрасываются или поглощаются соседними.

**Параметр:**
- `--min-region N` (4–200) — минимальный размер региона. Меньше → мельче прямоугольники, больше деталей

### PCA-прямоугольники

Каждый найденный регион — облако пикселей произвольной формы.
Из него извлекается ориентированный прямоугольник через **PCA (анализ главных компонент)**:

1. Строится матрица ковариации координат пикселей
2. Первый собственный вектор — главная ось (направление максимальной дисперсии)
3. Прямоугольник выравнивается по этой оси → он повёрнут на `seg.angle` градусов
4. Центр прямоугольника `(seg.cx, seg.cy)`, размеры `(seg.width, seg.height)`

Это даёт прямоугольники под углом, повторяющие форму объектов на кадре.

### Результат сегментации

`segments.json` — массив кадров, каждый кадр = массив объектов:

```json
{
  "cx": 312, "cy": 180,       // центр прямоугольника в пикселях
  "width": 48, "height": 22,  // размеры
  "angle": -12.4,             // угол поворота в градусах
  "clusterId": 7,             // номер цветового класса
  "color": [220, 185, 140]    // RGB приближённого цвета региона
}
```

## Шаг 2 — Рендер (`mosaic render`)

### Индекс ассетов

Перед рендером один раз строится `index.json` (`mosaic index-assets`):

- Каждая фотография сжимается до 160×160 JPEG → кэш-файл
- Вычисляется **взвешенный средний оттенок** (circular mean по Hue, вес = S×V + 0.01 — яркие насыщенные пиксели важнее серых)
- Сохраняются: `hue`, `saturation`, `value`, `avgR/G/B`

При рендере грузятся только 200 случайных кэш-файлов из индекса — никакого resize на лету.

### AssetScheduler — распределение ассетов по сегментам

Для каждого `clusterId` строится **ранг** — список индексов ассетов, отсортированных по евклидовому расстоянию в RGB-пространстве от `seg.color`:

```
dist = (avgR - seg.R)² + (avgG - seg.G)² + (avgB - seg.B)²
```

Каждый кластер имеет `rankIdx` — текущую позицию в ранге.
Каждые 0.2–1.0 сек (рандомно) `rankIdx` сдвигается на +1 → тайл меняется на следующий по похожести.

**Устранение повторов внутри кадра:**
Если в кадре 40 жёлтых сегментов, все они принадлежат одному `clusterId`. Без специальной логики все 40 получили бы один и тот же ассет.
Решение: каждый сегмент получает `siblingIdx` — порядковый номер внутри своего кластера в данном кадре. Итоговый индекс:

```
assetIdx = ranked[(rankIdx + siblingIdx × 7) % ranked.length]
```

Множитель 7 (простое число) — чтобы шаг не совпадал с кратными размерами ранга и картинки не образовывали паттерн.

### Сборка кадра

На каждый выходной кадр:

1. Создаётся чёрный RGBA-буфер `width × height`
2. Для каждого сегмента:
   - В режиме `--mode photo`: берётся кэш-файл ассета, resize до `(tileW × tileH)`, опционально поворот на `seg.angle`
   - В режиме `--mode solid`: создаётся буфер залитый `seg.color` нужного размера
3. Все тайлы composit'ятся через `sharp.composite()` пачками по 200
4. Итоговый буфер отправляется в ffmpeg через pipe

### Видео через ffmpeg

`openVideoStream` открывает ffmpeg с настройками:
- Кодек: `libx264`, пресет `fast`, `yuv420p`
- Входной формат: сырые RGBA-кадры через stdin pipe
- Выход: mp4 или gif

## Параметры — шпаргалка

| Параметр | Шаг | Что меняет | Диапазон |
|----------|-----|-----------|----------|
| `--tones N` | frames | квантование яркости | 4–14 |
| `--hues N` | frames | квантование оттенка | 4–14 |
| `--min-region N` | frames | мин. размер прямоугольника в пикселях | 4–200 |
| `--fps N` | frames + render | частота кадров | 6–24 |
| `--duration S` | render | длина выходного видео в секундах | — |
| `--mode photo\|solid` | render | фото-тайлы или чистый цвет | — |
| `--format mp4\|gif` | render | формат выхода | — |

**Правило:** при изменении `--tones`, `--hues`, `--min-region` нужно пересчитать `mosaic frames`.
Всё остальное — только `mosaic render`.

---

## Инструменты

| Инструмент | Роль |
|-----------|------|
| **sharp** | resize, rotate, composite, JPEG encode/decode, raw RGBA буферы |
| **ffmpeg** | извлечение кадров из видео, финальная сборка mp4/gif через pipe |
| **ffprobe** | определение длины и размеров видео |
| **Node.js** | весь процессинг: BFS, PCA, scheduler, index |
| **TypeScript / tsx** | компиляция и запуск без build-шага |
| **Pexels API** | скачивание фотографий по темам |

## Типичный запуск

```bash
cd packages/cli

# 1. Один раз: проиндексировать ассеты (строит кэш 160×160 + index.json)
npx tsx src/index.ts mosaic index-assets \
  --assets ../../assets/downloaded/photos \
  --extra ~/Projects/datasets/102flowers/jpg

# 2. Сегментировать входное видео
npx tsx src/index.ts mosaic frames \
  -i ../../assets/input/input-test-3-clip.mp4 \
  -o ../../batch-out/my-frames \
  --fps 12 --tones 6 --hues 6 --min-region 4

# 3. Рендерить (повторять с разными --mode без пересчёта frames)
npx tsx src/index.ts mosaic render \
  --segments ../../batch-out/my-frames/segments.json \
  --assets ../../assets/downloaded/photos \
  -o ../../batch-out/my-result.mp4 \
  --duration 10 --fps 12 --mode solid
```
