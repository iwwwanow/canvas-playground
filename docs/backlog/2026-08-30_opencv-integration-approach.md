# OpenCV как ингредиент, не архитектура

OpenCV не закрывает функционал xtc-toaster — это библиотека алгоритмов над одной картинкой (`Mat`: блюры, морфология, детекция краёв, цветовые преобразования), без понятия слоя/стека/blend mode/opacity-композитинга. Использовать её стоит точечно — как источник конкретного фильтра внутри одного эффекта, — а не как замену domain-слою.

Формат данных `Mat` структурно похож на `ImageRawDataArray` (плоский байтовый буфер, построчно), но с двумя ловушками: цвет по умолчанию хранится в **BGR**, не RGB, и поддерживаются произвольная битность/число каналов (не только 8-bit RGBA). При обмене данными нужен явный конвертер.

На границе с infrastructure — не класс-обёртка над всем API OpenCV (преждевременная абстракция, обернёт функционал, которым ещё не пользуетесь), а тонкий serializer: пара функций `toMat`/`fromMat` (свап каналов + приведение типа) плюс минимальные вызовы под конкретные операции, которые реально нужны в конкретном тосте. Тот же стиль, что уже есть в `domain/services/*.ts` — плоские функции, не классы.
