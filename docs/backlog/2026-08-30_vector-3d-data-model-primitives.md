# Хранение и модификация векторных/3D-данных — кирпичики для вайб-код редактора

Вопрос не в отрисовке (это тривиально — любой рендерер снимает `ImageData` в существующий reducer), а в том, какие примитивы нужны для хранения и модификации самих данных — это и есть будущие строительные блоки, из которых LLM будет собирать интерфейс.

**Вектор**: данные — это не SVG-строка, а разобранная в память структура (список путей → подпутей → точек-якорей с опциональными безье-хендлами). Нужные операции для модификации: геометрические трансформы (matrix translate/rotate/scale), редактирование точек пути (добавить/удалить/сдвинуть якорь, подвинуть контрольный хендл), булевы операции над путями (union/intersect/subtract/xor — вычислительная геометрия, нетривиально), упрощение/сглаживание пути (Douglas-Peucker, Catmull-Rom), stroke→fill конвертация, hit-testing (point-in-path для выделения), bounding box, интерполяция путей (морфинг для анимации). Экосистема здесь зрелая: `paper.js` закрывает почти весь список из коробки (полноценная сцена + boolean ops + редактирование путей), плюс точечные библиотеки — `bezier-js`, `martinez-polygon-clipping`/`polybooljs` (булевы операции отдельно), `svgpath` (парсинг/трансформация path-строк), `simplify-js`.

**3D**: модель данных — vertex buffer (позиции/нормали/UV) + index buffer (грани/треугольники) + материалы + scene graph (иерархия трансформов parent-child) + опционально скелет/кости для анимации. Это ровно то, что описывает структура glTF (scenes/nodes/meshes/accessors/animations) — хороший референс модели данных, не только формата экспорта. Хранение и scene graph здесь закрывает сам three.js (`BufferGeometry`, иерархия `Object3D`, `AnimationMixer`, `GLTFLoader`/`GLTFExporter`) — это не только рендерер.

**Главный вывод**: асимметрия сложности между вектором и 3D — не в форматах хранения (оба простые), а в зрелости инструментов *модификации*. Для вектора есть готовый полнофункциональный кирпич (`paper.js`) — редактирование путей, буллевы операции, всё уже решено в опенсорсе. Для 3D аналогичного кирпича не существует: рендеринг и хранение (three.js) есть, а вот полноценное редактирование меша (extrude, subdivide, CSG-булевы операции над солидами) — либо ограниченные/медленные библиотеки (`three-bvh-csg`, `three-csg-ts`), либо вообще ничего лёгкого в JS-экосистеме. Настоящий редактор мешей уровня Blender — это отдельный движок, который придётся либо писать самому, либо оборачивать что-то тяжёлое (OpenCascade/CGAL в WASM, headless Blender). Это и объясняет интуицию «3D не могу представить как реализовать» — проблема не в понимании, а в реальном отсутствии готового строительного блока под модификацию геометрии.
