# Финальная архитектура рендер- и экспорт-стека

Финальное решение (отменяет план на libvips из `docs/backlog/2026-08-30_sharp-libvips-integration.md` — тот файл остаётся как история разбора "что есть у либы / чего нет", но выбор C-либы поменялся с libvips на Skia).

Изображения и видео — не два отдельных пакета, а **одна библиотека**: рендер-стек (Bun/Zig/Skia) и видео-стек (ffmpeg через bun-layer) живут внутри одной и той же lib, не разносятся на разные пакеты.

## Изображения / слои

- **Bun** — хост-рантайм, FFI ко всем внешним C/C++ либам через `bun:ffi`
- **Zig** — оркестрация: доменная модель слоёв (opacity→alpha bake, порядок, привязка эффектов к слою), плюс вся специфичная логика, которую готовая либа не покрывает как единый вызов: HSV-маска с квадратичным falloff, hue-noise, lch-hue compose, reducer, решение гомографии по 4 точкам (`homographyFromPairs`)
- **Skia** — вся "база" низкоуровневой пиксельной обработки: blend modes (весь Photoshop/SVG-набор из коробки), affine/perspective warp, blur. Работает и на CPU-raster, и на GPU (Vulkan/Metal/D3D12 под капотом), переключение прозрачно для вызывающего кода — не нужно писать шейдеры руками (WGSL/GLSL) и трогать графическое API напрямую

Причина замены libvips на Skia: обе библиотеки закрывали пересекающийся набор операций (blur/composite/geometry), Skia дополнительно даёт GPU-путь бесплатно — держать обе C-либы одновременно избыточно, весь низкий уровень пиксельной обработки закрывает одна.

## Видео (секвенции, сборка, экспорт/импорт)

- **ffmpeg** как внешний процесс — всё "мясо" (кодеки, контейнеры, форматы) не через биндинги к libav*, а через CLI-флаги
- **Bun-layer** проксирует флаги в ffmpeg-процесс, но не как открытую трубу: фиксирует явный узкий контракт — только те настройки ffmpeg, что реально нужны продукту, вынесенные в собственный typed-интерфейс, а не всё пространство опций ffmpeg
- **Zig** в эту часть не лезет — видео-пайплайн целиком проксируется через bun-layer

## Следующие шаги

- Вручную подготовить спецификацию нужных методов Skia (не всё API — только тот срез, что реально нужен: blend modes, affine/perspective, blur) и нужных ручек на стороне Bun (FFI-контракт)
- В спецификации — юз-кейсы, не только сигнатуры методов
- Зарисовать схемы (границы между Bun/Zig/Skia/ffmpeg, поток данных)
- Подготовить TS-класс `Toast` — единая точка управления всем стеком: импорты, экспорты, анимации, рендер статики

## Общий принцип (см. также память `xtc-toaster_build-vs-buy`)

Готовое — по умолчанию; своё — только то, что либа физически не может закрыть (доменная модель слоёв, специфичные эффекты) или то, что является сутью продукта. Цель — прототип за ~полгода, а не переписывание инфраструктуры с нуля.
